# Coolify Trading + Market Data Bot v019

Бесплатный Telegram-бот без OpenAI API. Есть два независимых режима: **Анализ** — бот сам делает свежий рыночный анализ и выдаёт компактный финальный вердикт; **Parquet** — бот не выбирает LONG/SHORT, а только собирает свежие сырые данные, отправляет ZIP в Telegram и затем те же байты в Gmail как `.zip.jpg` для анализа в другой среде ChatGPT.

## v019: актуальная цена в локальном вердикте + читаемое форматирование

Локальный финальный вердикт теперь выводится в Telegram с жирным `LONG/SHORT`, тикерами, числовыми значениями и `NO TRADE`. После выбранного тикера показывается актуальная цена на момент сканирования: Binance Spot `lastPrice` для крипто и MEXC Futures `lastPrice` для XAU/XAG/USOIL. Цена всегда печатается обычным десятичным числом без `E...`; для дешёвых монет точность автоматически увеличивается, а лишние хвостовые нули удаляются.

### Сохранённые возможности предыдущего релиза

Локальная кнопка **Анализ** сохраняет прежнюю архитектуру, но сырьевой порог теперь можно менять прямо из Telegram. По умолчанию для XAU/XAG/USOIL используется `score = 5.0`. Команда `/score_s 4.5` меняет единый порог для всех трёх сырьевых активов; `/score_s` показывает текущее значение, `/score_s reset` возвращает `5.0`. Настройка хранится в обычном persistent state `/app/storage/state/bot_state.json`, поэтому переживает restart/redeploy. Криптовалютный порог остаётся отдельным и фиксированным `7.0`.

Для каждого XAU/XAG/USOIL теперь в полном журнале отдельно записываются LONG и SHORT: итоговый score, действующий threshold, результат `qualifies/below_threshold`, trend-компонента, macro/news/15m adjustment, extension penalty, silver penalty, тренды 1D/4H/1H, setup status и `completion_pct`. Это позволяет видеть реальную причину `NO TRADE`, а не только финальный `score=-999` у заглушки.

`/log_full` теперь выдаёт **строго последние 24 часа**. Выбран 24-часовой диапазон: он покрывает полный торговый день, ночные/дневные циклы и несколько запусков таймера 1–4 часа, но не позволяет журналу бесконечно разрастаться. На диске `full.log` ротируется каждый час и хранит 24 ротации; сам экспорт дополнительно фильтрует записи по timestamp, включая продолжения traceback.

Экономический календарь исправлен: публичный Forex Factory JSON используется для текущей недели, а вместо несуществующего `ff_calendar_nextweek.json` бот получает фактическую страницу `calendar?week=next` и разбирает её как fallback для горизонта 3–14 дней. Если next-week HTML недоступен, основной анализ не падает и в `/log_full` остаётся явный статус источника.

Локальный анализ по-прежнему использует Binance Spot для крипто и MEXC Futures для `XAU_USDT`, `SILVER_USDT`, `USOIL_USDT`; Yahoo не используется. Для крипто берутся до 365 закрытых 1D, 4H/1H и до 288 закрытых 15m свечей; неполная история новых листингов сохраняется. Используются breadth top-100, Binance Spot depth, MEXC funding/basis/OI и RSS/news. `READY` требует согласования 1D/4H, 15m-подтверждения и отсутствия входа из середины диапазона.

Для каждого реально выбранного актива финальный локальный вердикт показывает `Отработка: N%`. Это расчётная эвристическая оценка текущего сетапа при выполнении условия входа, а не исторический winrate и не гарантия результата.

Parquet collector, Gmail delivery, порядок Telegram→Gmail и логика таймера не менялись. `collector.py` сохранён byte-for-byte.

## Кнопки

```text
[ Анализ ]   [ Время выкл ]
[ Parquet ]  [ Почта ]
[ Пинг ]
```

- **Анализ** — то же, что `1` или `/scan`; бот сам делает анализ.
- **Время ...** — `выкл → 15 мин → 30 мин → 1 час → 4 часа → выкл`.
- **Parquet** — то же, что `/parquet`; только сбор данных, без выбора LONG/SHORT.
- **Почта** — то же, что `/gmail`.
- **Пинг** — версия, Telegram latency, uptime, RSS-память.

Старые текстовые названия `Отправить parquet` и `Подключить почту` также принимаются как совместимые алиасы, но на клавиатуре больше не показываются.

### Команды

- `/help` — кратко показывает источники данных, режимы и команды.
- `/score_s` — показать текущий порог сырья.
- `/score_s 4.5` — установить единый порог для XAU/XAG/USOIL; допускается и запятая `4,5`.
- `/score_s reset` — вернуть порог сырья `5.0`.
- `/log_full` — журнал только за последние 24 часа.
- `/status` — состояние бота; также показывает текущий сырьевой score.
- `/scan`, `/parquet`, `/ping`, `/gmail`, `/cancel` — прежние команды без изменения поведения.

Ниже score — больше сырьевых кандидатов и мягче фильтр; выше score — меньше сигналов и строже отбор. `/score_s` влияет только на локальный XAU/XAG/USOIL-анализ и не меняет Parquet или криптовалютный порог `7.0`.

### Как работает «Время»

Выбор интервала сам ничего не запускает. После выбора нажмите **Анализ** или **Parquet**. Бот будет циклически повторять именно выбранное действие. Новый интервал отсчитывается после полного завершения предыдущего запуска. Ручное нажатие другого действия переключает автодействие на него. При `Время выкл` действие выполняется один раз.

## Анализ

Локальный алгоритм без LLM/API использует Binance Spot 1D/4H/1H/15m, market breadth, компактный Spot order book, MEXC funding/basis/futures context, календарь ключевых событий и RSS/news. XAU/XAG/USOIL полностью анализируются по MEXC Futures на 1D/4H/1H/15m; Yahoo не используется. Результат — только `ФИНАЛЬНЫЙ ВЕРДИКТ · v019` с расчётной строкой `Отработка: N%` у каждого выбранного актива.

## Parquet

### Crypto timeframes

Бот формирует 100 наиболее капитализированных non-stable/non-wrapped активов с активной Binance Spot `USDT` парой. Для каждого собираются только полностью закрытые свечи:

- до **999 × 1H** (~41.6 дня);
- до **365 × 1D**;
- до **288 × 15m** (последние 3 дня).

Для нового листинга короткая история допустима и помечается `PARTIAL_HISTORY`. Это относится и к 1D: если у тикера есть, например, только 80 или 200 закрытых дневных свечей, тикер **не исключается** и не заменяется другим — в архив попадает вся доступная история до лимита 365. 4H в последующем анализе строится из 1H.

### Market breadth и Binance Spot liquidity

`market_breadth.parquet` рассчитывается локально по top-100: advance/decline, positive breadth, median returns, доля активов выше SMA20/50/200 1D, relative breadth к BTC, новые 20D high/low.

`binance_spot_liquidity.parquet` содержит свежий snapshot стакана Binance Spot: spread, depth и imbalance в диапазонах ±0.1%, ±0.5% и ±1.0%, плюс фактическое покрытие полученных уровней.

### MEXC Futures

`funding_mexc.parquet` сохраняет current funding и последние 30 funding settlements. `mexc_derivatives.parquet` добавляет current `holdVol`/OI, last/fair/index, basis, funding, 24h futures volume и bid/ask. Binance Futures не используется.

### BTC/ETH options

Deribit public API используется без торговых ключей как **необязательный enrichment-слой**. Если Deribit отвечает, `options_deribit.parquet` хранит snapshot активной BTC/ETH option-chain, а `options_regime.parquet` — компактный regime: put/call OI/volume, ATM IV около 7/30/60 дней и DVOL. Если Deribit не отвечает или возвращает непригодные данные, сбор архива не падает: options пропускаются, остальные данные и ZIP формируются как обычно.

### XAU / XAG / USOIL

MEXC Futures: `XAU_USDT`, `SILVER_USDT`, `USOIL_USDT`. Для каждого также собираются до 999×1H, 365×1D и 288×15m закрытых свечей.

## Состав ZIP

```text
market_scan_YYYYMMDD_HHMMSS.zip
├── crypto_ohlcv_1h.parquet
├── crypto_ohlcv_1d.parquet
├── crypto_ohlcv_15m.parquet
├── commodities_ohlcv_1h.parquet
├── commodities_ohlcv_1d.parquet
├── commodities_ohlcv_15m.parquet
├── market_breadth.parquet
├── binance_spot_liquidity.parquet
├── funding_mexc.parquet
├── mexc_derivatives.parquet
├── options_deribit.parquet      # только если Deribit доступен
├── options_regime.parquet       # только если Deribit доступен
├── universe.parquet
├── PROMPT_FOR_CHATGPT.txt
├── manifest.json
└── status.json
```

`PROMPT_FOR_CHATGPT.txt` требует анализировать 1D → 4H → 1H → 15m, derivatives/liquidity/breadth, а BTC/ETH options — только если соответствующие файлы реально есть в архиве. Перед финальным вердиктом обязательно проверяется через свежий интернет макро, новости, token unlocks, регуляторные события и геополитическая/военная эскалация. В финальном блоке LONG/SHORT, тикеры и все числовые значения выделяются жирным; для действительно исключительного сигнала разрешена отдельная строка `**ВНИМАНИЕ! ПОВЫШЕННАЯ ПРОХОДИМОСТЬ!**`.

## Telegram → Gmail

Для **Parquet** порядок строгий:

1. Telegram получает `market_scan_....zip` без `.jpg`.
2. После этого Gmail получает точно те же ZIP-байты с именем `market_scan_....zip.jpg` и MIME `image/jpeg`.

Для распаковки почтового вложения удаляется только последний `.jpg`. Перед Gmail-отправкой бот повторно проверяет размер и SHA-256 и использует ledger защиты от дублей.

## Почта / Gmail

В v019 основной способ подключения — **быстрый импорт уже существующей Gmail-сессии**. Нажмите **Почта** и отправьте одной строкой Base64-экспорт из старого бота. Сообщение с экспортом бот сразу удаляет, расшифровывает данные только в памяти и проверяет Google-сессию без отправки тестового письма.

Импортированная авторизация **сессионная**: Client ID/Secret, refresh token, access token и Fernet key из импорта не записываются на диск и исчезают после restart/redeploy нового бота. После redeploy достаточно снова нажать **Почта** и отправить ту же строку. Старый бот при этом не изменяется и его OAuth-доступ не отзывается.

Google OAuth/callback в v019 не используется: кнопка **Почта** работает только через импорт сохранённой сессии.

## Полный лог

Команда `/log_full` присылает только записи за **последние 24 часа**: входящие команды/кнопки, запуск и завершение анализа/Parquet, стадии сборки, таймеры, Telegram/Gmail delivery, Gmail OAuth-аудит и ошибки. Для XAU/XAG/USOIL дополнительно логируются LONG/SHORT candidate score, действующий threshold и все основные компоненты score до финального отсева. Для Market Scan логируются состав top-100, покрытие и `PARTIAL_HISTORY` для 1H/1D/15m, Binance Spot depth/liquidity, market breadth, MEXC funding, OI/basis, XAU/XAG/USOIL по таймфреймам, доступность BTC/ETH options, а также итоговый размер/SHA-256/время сборки ZIP.

На диске `full.log` ротируется каждый час с `backupCount=24`; поэтому новый журнал физически ограничен примерно одним днём работы, а экспорт `/log_full` применяет точное 24-часовое окно по UTC timestamp.

Секретные значения в журнал не передаются: содержимое Gmail import, Client Secret, access/refresh tokens, Bearer Authorization, Fernet key/token и Telegram bot token не логируются либо автоматически редактируются. Обычные произвольные текстовые сообщения также записываются только как факт получения и длина, без текста.

## Coolify

Для обычного развертывания вручную задаётся только:

```env
TELEGRAM_BOT_TOKEN=...
```

`compose.yaml` использует `GMAIL_SESSION_ONLY=true`: импортированная Gmail-авторизация специально не переживает redeploy. Persistent volume `/app/storage` сохраняет обычное состояние бота, архивный ledger и журналы, но не импортированную Gmail-сессию. Публичный Gmail callback и `SERVICE_URL_GMAILAUTH_80` для подключения почты не требуются.

Подробно: `COOLIFY.md`.

## Status

`/status` показывает v019, текущее действие, таймер и следующее выполнение, текущий сырьевой score, статистику самостоятельного анализа, последний Parquet, размер ZIP, покрытие Binance Spot/MEXC funding/XAU-XAG-USOIL, Gmail status и память процесса.
