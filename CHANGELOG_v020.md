# v020

- Добавлена защита от кратковременных сетевых `ConnectTimeout` при доставке готового результата в Telegram.
- Для финального **Анализа** и Telegram-архива **Parquet** используется до трёх попыток подключения: первая попытка с `connect_timeout=5 c`, затем повтор через `2 c`, затем последний повтор через `3 c`.
- Повтор выполняется только для подтверждённой ошибки установления соединения (`httpx.ConnectTimeout`/`ConnectError`). Неопределённые read/write timeout не повторяются, чтобы не отправить один и тот же вердикт или архив дважды, если Telegram уже успел принять запрос.
- Служебные progress-сообщения `⏳ Сканирую рынок…`, `⏳ Собираю свежий Parquet…` и `UPLOAD_DOCUMENT` не повторяются. Если Telegram временно недоступен, их ошибка логируется, но сам анализ/сбор продолжается.
- Если готовый Анализ не удалось доставить после трёх connect-попыток, результат текущего круга пропускается; таймер остаётся жив и следующий круг запускается по прежнему интервалу.
- Если Telegram-архив Parquet не удалось доставить после трёх connect-попыток, текущий круг доставки пропускается и Gmail для этого архива не запускается, сохраняя прежний обязательный порядок `Telegram → Gmail`.
- Автоцикл дополнительно защищён от вышедшего наружу `telegram.error.NetworkError`, чтобы временная проблема Telegram не завершала задачу `auto-action-*`.
- Алгоритм локального анализа, рыночные расчёты, источники данных и логика сборки Parquet-свечей не менялись. `collector.py` сохранён byte-for-byte; `analyzer.py`, `market_data.py` и `signal_stats.py` отличаются от предыдущего релиза только строками версии `v020`.
- Версия обновлена на `v020` в runtime-коде, Docker metadata, документации, prompt, VERSION и self-test файлах.
